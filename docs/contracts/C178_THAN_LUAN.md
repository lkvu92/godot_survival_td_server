# C178 — Thần Luân

Version: 2.2.0 | Status: ACTIVE | Date: 2026-10-23

## Gate 1: agreed contract
Feature `laws` is Thần Luân at account level 35. Character/server scoped, shared by owned heroes. Free level 1, maximum 50. Profile `than_luan={level:int,revision:int}`; immutable balances/stats are never accepted from clients. Missing state is reconciled on server only. Config `progression.than_luan={schema_version:2,unlock_level:35,max_level:50,charm_item_id:than_luan_boost_charm,charm_multiplier:1.5,levels:[{level,aura_id,stats,success_rate,cost:{item_id,quantity,gold}}]}`. Runtime stats are fractions: persistent_damage_reduction=.003L, dot_damage_reduction=.006L, control_duration_reduction=.008L. Level 0 grants zero.

## RPC and service interfaces
`get_than_luan_state {}` and `upgrade_than_luan {request_id,expected_level,expected_revision,use_charm}` use account/character/version/feature guards. Response `{success,state:{level,revision,stats,aura_id,next,materials,gold_owned,charm_item_id,charm_multiplier},profile,inventory,attempted,consumed,upgraded,charm_consumed,success_rate,previous_level,new_level}`. `success=true` means the attempt was committed; only `upgraded=true` increases the level. Every paid attempt increments revision, including failures. A replay returns the stored original outcome with the latest authoritative state, without RNG or another debit. Upgrade checks authentic level and release, consumes configured fragments, gold and optionally one selected charm, and atomically commits profile, inventory and durable request receipt. Request identity binds level, revision and charm selection. Replays are free, conflicting expected level fails. Client retries an uncertain upgrade with the same request ID. No local profile, reward or gameplay config fallback; malformed/missing config blocks actions. `ThanLuanService.changed` refreshes UI from confirmed responses and profile updates.

Dedicated consumable `than_luan_boost_charm` (Pháp Tắc Phù), rare, stackable 999999, context `than_luan`, multiplier 1.5, icon `divine_wheel_boost`. Ngộ Đạo Phù remains exclusive to Linh Căn; it cannot substitute or be consumed here. The shared picker only offers ads for explicitly registered item placements.

## Economy
Target 2..10 low costs 30+8(T-2); 11..20 medium 50+10(T-11); 21..30 high 20+4(T-21); 31..40 high 45+5(T-31); 41..50 high 80+8(T-41). Totals 558 low,950 medium,2215 high. Gold per target T: 2..10 = 10+4(T-1); 11..20 = 50+10(T-11); 21..50 = 200+20(T-21). Failure consumes all selected costs, leaves level/stats unchanged, and never downgrades. No conversion or separate breakthrough. Base chance at target T is talisman success_rates_by_current_level[floor((T-2)*29/48)] for T=2..50, snapshotted into authoritative per-level rows. Selected dedicated Pháp Tắc Phù multiplies base by 1.5, rounded half-up and capped at 100. Original fragment totals are the all-success minimum, not a guaranteed farm duration after introducing failures. Existing tower rewards remain unchanged.

## Battle integration 2.2
Campaign, breakthrough and tower bind an immutable server-issued aura row at battle entry, including an explicitly empty row for locked users. Breakthrough stores its row in the authoritative encounter state and returns it on start. Shared HUD shows aura level and all three active reductions from the actor snapshot; BattleStatsDialog includes aura level and cosmetic visibility. Hiding the visual does not disable permanent stats. Actor halo uses hero-head geometry (diameter 1.17H, center 0.12H below the top), independent of facing. No demon inherits the player aura.

## Combat
Snapshot at activity entry, never add to persisted hero base stats, never reapply on draft/level changes. Player campaign/tower/tribulation receive stats, demon does not. Add optional trailing `is_dot=false` to Player.take_damage; only burn/poison/poison_percent/bleed ticks set it. General and DOT reduction multiply before shields; true damage bypasses both. Resolve harmful canonical control duration then shorten exactly once, including refresh/extend. Existing RNG resistance remains independent. EHP rating includes only general reduction via 1/(1-r), with client/server parity and separate breakdown; conditional stats are visible, not scored.
