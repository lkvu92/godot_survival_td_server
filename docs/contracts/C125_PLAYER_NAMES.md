# C125 — Player names, one-time rename and profanity filter

- Version: `1.2.0`
- Status: `ACTIVE`
- Date: `2026-11-04`

1.2.0 adds bilingual (Vietnamese & English) profanity, toxicity and sensitive keyword filtering for character naming and rename requests (`rename_player`). Input display names must pass validation against `profanity_filter.json` rules:
1. System Reserved Keywords: rejects identity markers (`admin`, `administrator`, `gm`, `gamemaster`, `bqt`, `banquantri`, `cskh`, `moderator`, `hethong`, `system`, `server`, `official`).
2. Single-Word Vulgar Tokens: enforces exact word boundary matching for high-risk short profanities (`cac`, `cặc`, `lon`, `lồn`, `dit`, `địt`, `ass`, `cum`, `dm`, `vcl`, `dkm`...) to prevent false positives on valid composite words.
3. Vulgar Compound Phrases: inspects phrase substring matches (`dit me`, `địt mẹ`, `du ma`, `đụ má`, `motherfucker`, `thang cho`...) including punctuation and whitespace delimiter-collapsed variations (`d.k.m`, `d_m`, `f.u.c.k`...).
4. Canonicalization & Accents: converts to lowercase Unicode NFC, translates leetspeak homoglyphs (`0`->`o`, `3`->`e`, `4`->`a`, `@`->`a`, `$`->`s`...), and evaluates both accented and unaccented text streams.
5. Whitelist & False Positive Protection: explicitly whitelists legitimate Vietnamese single words (`Long`, `Phúc`, `Khang`, `Bác`, `Cát`, `Cúc`, `Bích`, `Tích`, `Dung`), common Xianxia/Wuxia compound names (`Thăng Long`, `Bạch Long`, `Bác Ái`, `Thác Bản`, `Tác Giả`, `Các Hạ`, `Cát Tường`, `Phúc Khang`, `Bách Thắng`, `Bích Dao`, `Hàn Lập`, `Tiêu Viêm`, `Thanh Vân`), and legitimate English substrings (`Assassin`, `Classic`, `Cassandra`, `Entity`, `Title`).
RPC errors return explicit machine-readable and localized messages: `NAME_CONTAINS_PROFANITY` (400, "Tên chứa từ ngữ không phù hợp."), `NAME_RESERVED_KEYWORD` (400, "Tên chứa từ khóa của hệ thống hoặc Ban Quản Trị."), `NAME_INVALID_FORMAT` (400, "Tên cần từ 3 đến 24 ký tự, không chứa ký tự điều khiển hoặc ký hiệu định dạng."). Godot client runs local validation in `RenamePlayerDialog` with `UiSkin` warning state prior to invoking RPC.

1.1.0 supersedes the one-time-only policy below: one free rename per account since creation; later renames consume rename_talisman (Thẻ đổi tên) x1. Counter is the monotonic total, reconciled with MAX(profile, durable identity) and never clamped to one. Inventory/card debit, profile and identity commit atomically. Same-name retries never spend another card. UI refreshes authoritative eligibility on open, distinguishes free vs item-paid, displays owned cards and disables unavailable actions. C129 defines catalog/prices. Offline/validation/CAS/account switch cannot spend an item.

Google's Nakama username is an internal random identifier, separate from the game display name. On server profile bootstrap/repair, Google accounts with blank names or names equal to that generated username receive a persistent random game name `Tu Giả XXXXXX`. Email accounts use their registered username. Existing custom names remain unchanged. No local or hardcoded personal-name fallback.

`rename_player {display_name}` authenticated, account-guarded RPC accepts trimmed 3–24 Unicode characters, no control characters, zero-width formatting characters or markup delimiters, and validated against the profanity filter. Returns `{success,display_name,name_changes_used:1}`. A profile may rename once free, enforced by an atomic versioned storage batch updating the profile and a server-owned `player_identity/name {display_name,name_changes_used}` record. The identity record is authoritative even if delayed gameplay writes contain stale profile fields. Same-name retry after success is idempotent; invalid, unchanged-before-use, failed or concurrent rejected requests do not spend the chance or item. General profile saves cannot change display_name or name_changes_used. Merge conservatively preserves the maximum spent count in both identity and chosen profile. Names are display labels, not unique login identifiers; email/Google/user IDs remain unchanged.

Profile includes Đổi tên, remaining chance, input in shared Login skin and an explicit confirmation before mutation. Busy state prevents repeat/cancel. UI uses UiDialog/UiSkin/AtlasRegistry; text supports Vietnamese accents. Successful server response updates UserContext and Home/Profile via name_changed. Offline operations fail without modifying local identity. Unknown network result is resolved by reloading profile on retry; CAS/idempotency prevents double changes.
